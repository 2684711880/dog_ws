# 四足机器人运动控制 重构方案 v2

> v1 → v2 关键修订（按重要性排序）：
>
> - **复用 `motor_ros2/leg_model.h`**：不再发明 `JointAngles/kNumJoints`，所有腿/关节身份用 `lm::LegId / JointId / QuadJoints` 这条真源。
> - **保留 ROS 接口语义**：`LocomotionCommand.height` 仍是"离地间隙偏移"（+1=抬高=偏移↓）；`/gait_params` topic 保留（`real_motor_controller` 的 PID 切换依赖它）；`input_source` 过滤保留。
> - **保留 STEPPING 步态**：`GAIT_STEPPING=1` 已在 `dog_msgs::msg::LocomotionCommand` 落地，重构不能丢。
> - **`LegConfig` 补齐机械量**：`knee_offset_rad`、`knee_gear_ratio`、`joint_signs[3]`、`joint_limits[3]`，并以"实测站立 foot 在 hip frame 下 = (FK(0,0,0))" 做自检。
> - **修 Bezier 摆动**：起飞/落地控制点改为同侧布置，保证 xy 速度连续 + 顶点高度可控。
> - **`compute_landing_target` 改为每周期更新**（不只是 liftoff 瞬间）。
> - **`CommandFilter` 保留 lowpass + slew 双段**（沿用 `command_filter_alpha`）。
> - **步态切换 blend 在足端空间**，不在关节空间。
> - **新增 `SafetyMonitor` 和 `Telemetry`** 两个职责模块。
> - **目录结构按现 workspace 多包对齐**：`dog_ws/src/{dog_msgs, dog_tool, dm_imu, dog_control, dog_teleop, dog_bringup}`。
> - **Phase 0**：单腿台架 + 测量自检，前置到所有编码之前。

## 一、当前代码的根本问题（仍然成立）

1. **没有腿坐标系** — 四条腿共享 `stand_foot_x/y`，前后腿 hip offset 不同但代码不区分
2. **开环执行** — 假设上一步完美执行，没有足端实际位置反馈
3. **planner 和 runtime 职责混乱** — 滤波、相位推进、轨迹生成、IK 搅在一起
4. **没有足端工作空间约束** — 靠运行时 IK 失败兜底（`continue` 跳过）
5. **支撑相速度曲线错误** — `smooth_step` 不匹配匀速体运动
6. **duty factor 写死 50%** — trot 无飞行相容忍度
7. **landing target 不在控制循环里更新** — 中段 vx 变化无法响应
8. **机械虚位 20mm 没在策略层显式约束** — 任何 `step_height < 40mm` 的步态都会拖地

## 三、与现工程真源的对接（新）

**绝对不重新发明的东西：**

| 现真源 | 用途 | 重构里怎么用 |
|---|---|---|
| `motor_ros2/leg_model.h` | LegId/JointId/QuadJoints/flatten/joint signs/limits | 直接 `using namespace lm` |
| `dog_msgs::msg::LocomotionCommand` | 速度+步态+height | 不改字段，不改语义 |
| `dog_msgs::msg::MotorFeedback` | 12 关节位置/速度/扭矩/温度 | 入 `RobotState` 做 FK |
| `/gait_params` topic | 给 `real_motor_controller` 切 PID gain | `LocomotionController` 在每个周期发布当前 active gait |
| `motor_cfg.h/.cpp`, DJI 3508 驱动 | 电机层 | 完全不动 |
| `xbox_input_node` | 摇杆 → `LocomotionCommand` | 完全不动 |
| `pose_hold_tool` | 标定/调试 | 完全不动 |

**保留的接口约定：**

- `LocomotionCommand.height` 是**离地间隙偏移**（与 `height_default` 加和；axis7=+1 让机器人抬高=`height` 数值降低）。控制器内部转换 `body_height = clamp(height_default + cmd.height_offset, height_min, height_max)`。
- `LocomotionCommand.source` 必须等于参数 `input_source`（默认 `xbox`）才生效，其他来源静默丢弃。
- `/gait_params` 的字符串与 `gait_config(...).name` 一致：`STAND / STEPPING / WALK / TROT`。

## 四、核心数据结构

```cpp
// ======================== include/quad/types.h ========================
#pragma once
#include "motor_ros2/leg_model.h"   // 真源, 不要重复定义
#include <array>
#include <cmath>

namespace quad {

namespace lm = motor_ros2::leg_model;

constexpr double kPI = 3.14159265358979323846;
constexpr double k2PI = 2.0 * kPI;

struct Vec3 {
    double x{0}, y{0}, z{0};
    Vec3 operator+(const Vec3& o) const { return {x+o.x, y+o.y, z+o.z}; }
    Vec3 operator-(const Vec3& o) const { return {x-o.x, y-o.y, z-o.z}; }
    Vec3 operator*(double s) const { return {x*s, y*s, z*s}; }
    double norm() const { return std::sqrt(x*x + y*y + z*z); }
};

// 单条腿的状态 (机器学/反馈层)
struct LegState {
    lm::LegJoints<double> joint_pos;     // 当前关节角 (joint-cmd 空间, 含符号映射后)
    lm::LegJoints<double> joint_vel;
    Vec3  foot_pos_hip;                   // FK 算出, hip 局部系 (X前 Y左 Z上)
    Vec3  foot_pos_body;                  // FK 算出, body 系
    bool  in_contact{true};               // 触地判断 (无足底力时用扭矩+扭矩阈值)
};

struct RobotState {
    std::array<LegState, lm::kLegCount> legs;
    Vec3 body_rpy{};                      // 来自 IMU, 没有则全 0
    Vec3 body_angular_vel{};
    double timestamp{0};
};

// 已滤波的运动指令 (内部口径, 不再带 height_offset 语义)
struct LocomotionCommand {
    double vx{0};
    double vy{0};
    double yaw_rate{0};
    double body_height{0.305};            // 绝对值, m, J1 到地面
};

enum class GaitType : uint8_t {
    STAND    = 0,   // 与 dog_msgs::LocomotionCommand::GAIT_STAND 对齐
    STEPPING = 1,
    WALK     = 2,
    TROT     = 3,
};

struct GaitParams {
    GaitType type{GaitType::STAND};
    double   frequency{1.5};
    double   duty_factor{0.65};
    double   step_height{0.05};           
    double   max_step_length{0.12};
    std::array<double, lm::kLegCount> phase_offsets{0, kPI, kPI, 0};
    bool     joint1_lock_zero{false};     // WALK 通常 true (节点说明 §6)
};

struct ContactSchedule {
    std::array<bool, lm::kLegCount>   in_stance;
    std::array<double, lm::kLegCount> phase_in_cycle;   // [0,1)
    std::array<double, lm::kLegCount> swing_progress;   // 摆动 [0,1], 否则 -1
    std::array<double, lm::kLegCount> stance_progress;  // 支撑 [0,1], 否则 -1
    double global_phase{0};                              // [0, 2π)
};

struct FootTarget {
    Vec3 position;        // body 系下足端目标 (X前 Y左 Z上)
    bool force_contact;   // 支撑相 true
};

struct JointCommand {
    lm::QuadJoints<double> positions;     // joint-cmd 空间
};

}  // namespace quad
```

**关键澄清：**

- `LegState.joint_pos` 与 `JointCommand.positions` 都在**关节命令空间**（已应用 `kJointSigns` 后），与 `pose_hold_tool` 直接发的 `/joint_states` 字段一致。电机驱动层再做"小圈映射 + 限幅"。
- `Vec3` 在 hip frame 与 body frame 都是 X 前 Y 左 Z 上的右手系。
- `GaitType` 枚举的整型值与 `dog_msgs::msg::LocomotionCommand::GAIT_*` 严格对齐，做 `to_gait_type` 转换时不能错位。

## 五、模块 1: 腿运动学 (LegKinematics)

```cpp
// ======================== include/quad/leg_kinematics.h ========================
#pragma once
#include "types.h"

namespace quad {

struct LegConfig {
    Vec3   hip_offset_in_body;    // hip 中心在 body 系下的位置, m
    double thigh_length{0.21};
    double shank_length{0.21};
    double knee_offset_rad{0.0};  // 大小腿并拢时的初始 J3, 默认 19° → 0.3316
    double knee_gear_ratio{2.0};  // J3 输出端 = 关节命令 × 2

    // joint-cmd 空间限幅 (rad), 与 lm::kJointLimits 对齐
    // 注意: 关节符号映射 (lm::kJointSigns) 由 hardware/main.cpp 在下发/反馈时统一处理,
    //       LegKinematics / FootPlanner / Controller 全程在"关节命令空间"工作,
    //       与 /joint_states topic、pose_hold_tool 同口径.
    lm::LegJoints<double> joint_min{-1.2, -1.2, -0.6};
    lm::LegJoints<double> joint_max{+1.2, +1.2, +2.4};

    // 站立标定: J1=J2=J3=0 时, FK 应得到这个 hip 系坐标
    Vec3 nominal_stand_foot_hip{0.08, 0.095, -0.305};
};

class LegKinematics {
public:
    explicit LegKinematics(std::array<LegConfig, lm::kLegCount> cfgs);

    // FK: 关节角 (joint-cmd 空间) → 足端位置
    Vec3 forward_kinematics(lm::LegId leg, const lm::LegJoints<double>& q) const;
    Vec3 forward_kinematics_body(lm::LegId leg, const lm::LegJoints<double>& q) const;

    // IK: 足端位置 (hip 系) → 关节命令角 (含 knee_offset 与 gear_ratio,
    //                                     左右腿对称口径, 与 /joint_states 一致;
    //                                     不做电机符号映射 — 那是 hardware/main.cpp 的事)
    bool inverse_kinematics(lm::LegId leg, const Vec3& foot_pos_hip,
                            lm::LegJoints<double>& q_out) const;
    bool inverse_kinematics_body(lm::LegId leg, const Vec3& foot_pos_body,
                                 lm::LegJoints<double>& q_out) const;

    // 工作空间
    bool is_reachable(lm::LegId leg, const Vec3& foot_pos_hip) const;
    Vec3 clamp_to_workspace(lm::LegId leg, const Vec3& foot_pos_hip) const;

    // 坐标变换
    Vec3 hip_to_body(lm::LegId leg, const Vec3& p_hip) const;
    Vec3 body_to_hip(lm::LegId leg, const Vec3& p_body) const;

    const LegConfig& config(lm::LegId leg) const;

    // 自检 (在构造或重新加载参数后必须跑一次)
    // 验证 FK(0,0,0) ≈ nominal_stand_foot_hip
    bool self_check(double tol_m = 5e-3) const;

private:
    std::array<LegConfig, lm::kLegCount> configs_;
};

}  // namespace quad
```

**IK 关键公式（含 knee_offset 与 gear_ratio，无符号映射）：**

设关节命令角 `q1, q2, q3`（与 `/joint_states` 同口径），几何输出端 J3 角度 `J3_geom`：

```
J3_geom = q3 / knee_gear_ratio + knee_offset_rad      // FK 时这样还原几何
q3      = (J3_geom - knee_offset_rad) * knee_gear_ratio  // IK 时反向

q1 = atan2(y_hip, x_hip)         // 左右腿对称, 不再乘 side sign
q2 = 平面三连杆 IK (与现 locomotion_planner.cpp 一致)
```

`forward_kinematics(...)` 内部把 (q1, q2, J3_geom) 直接做平面三连杆 FK；`is_reachable` 用 `[|l1-l2|, l1+l2]` 半径 + hip-yaw 限幅做 O(1) 判定，不调 `inverse_kinematics`。

电机端的"后腿 J1 反号"等镜像逻辑由 `real_motor_controller`（`hardware/main.cpp`）在订阅 `/joint_states` 后用 `lm::kJointSigns` 翻转一次，下发到 CAN 总线。

**`clamp_to_workspace` 算法（明确，不能模糊）：**

```
1. 把 p_hip 投影到 hip-yaw 限幅的扇区内 (绕 z 旋转)
2. 计算到 hip 中心的 3D 距离 d, 限到 [d_min + ε, d_max - ε]
3. 用扇区方向 + 限后距离重建 p_hip
```

`ε = 5 mm` 给 IK 数值稳定留 margin。

## 六、模块 2: 步态调度器 (GaitScheduler)

职责：只管相位推进与接触计划。

```cpp
class GaitScheduler {
public:

    ContactSchedule step(double dt);
    const GaitParams& gait_params() const { return params_; }
    void   reset_phase() { global_phase_ = 0.0; }
```

`step(dt)` 实现按 v1 一致（duty_factor 切支撑/摆动），`STAND` 时不推进相位、全腿支撑。

**预设步态（与 v1 节点说明里的实跑参数对齐）：**

| 步态 | freq Hz | duty | step_h | step_len | phase_offsets | J1 锁零 |
|---|---:|---:|---:|---:|---|:--:|
| STAND | — | 1.0 | 0 | 0 | 全 0 | 否 |
| STEPPING | 2.0 | 0.5 | 0.050 | 0 (锁) | LF=0, RB=0+δ, RF=π, LB=π+δ | 否 |
| WALK | 0.83 | 0.80 | 0.045 | 0.06 | LF=0, RB=0.5π, RF=π, LB=1.5π | **是** |
| TROT | 1.8 (起步 1.3) | 0.62 | 0.050 | 0.10 | LF=0, RF=π, LB=π, RB=0 | 否 |

`δ = stepping_diagonal_skew_rad ≈ 0.314`（保留现有参数）。

## 七、模块 3: 足端轨迹规划 (FootPlanner)

**核心修订（vs v1）：**
1. `compute_landing_target` **每个控制周期**重算（响应 vx 变化），不只在 liftoff。
2. Bezier 用**同侧抬起 + 同侧落下**的 5 控制点，保证起飞/落地 xy 速度=0。
3. `T_stance` 从 `gait_params` 派生：`T_stance = duty_factor / frequency`。
4. 支撑相位移用真实 `T_stance` 与"匀速线性"，不是 smoothstep。
5. STEPPING 时把 `step_len = 0` 强制为 0（vx/vy 均不映射到水平位移）。

```cpp
class FootPlanner {
public:
    explicit FootPlanner(const LegKinematics& kin);

    std::array<FootTarget, lm::kLegCount> plan(
        const RobotState&        state,
        const LocomotionCommand& cmd,
        const GaitParams&        gait,
        const ContactSchedule&   schedule,
        double                   dt);

private:
    Vec3 swing_trajectory(const Vec3& p0, const Vec3& p1,
                          double t, double step_height) const;

    // 修正版: 每周期都可调用; 用预测 hip 位置 (vx*Δt 前推)
    Vec3 compute_landing_target(lm::LegId leg,
                                const LocomotionCommand& cmd,
                                const GaitParams& gait,
                                double swing_remaining_time) const;

    const LegKinematics& kin_;

    struct LegMemory {
        Vec3 liftoff_pos{};         // body 系
        Vec3 landing_target{};      // body 系, 每周期更新
        Vec3 touchdown_pos{};       // body 系, 触地瞬间冻结

    };
    std::array<LegMemory, lm::kLegCount> memory_;

```

**Bezier 修订（5 控制点, xy 端点速度为零）：**

```
P0 = liftoff_pos               (起点)
P1 = liftoff_pos  + (0,0,h)    (同侧上提, 锁 xy 速度 = 0)
P2 = midpoint(P0,P4) + (0,0,2h) (顶点高于 step_height, Bezier 顶点取值 ~ 1.5h)
P3 = landing_target + (0,0,h)  (同侧上提, 锁落地 xy 速度 = 0)
P4 = landing_target            (终点)

四阶 Bezier:
B(t) = (1-t)^4 P0 + 4(1-t)^3 t P1 + 6(1-t)^2 t^2 P2 + 4(1-t) t^3 P3 + t^4 P4
```

约束 `step_height` 实际顶点：四阶 Bezier 顶点为 P2 高度的 6/16 ≈ 0.375 倍，于是 `P2.z = liftoff.z + 2.67·step_height`，仍以 `step_height` 作为期望峰值高度（保持调参一致）。

**Raibert 落脚点（每周期更新）：**

```cpp
Vec3 FootPlanner::compute_landing_target(
    lm::LegId leg, const LocomotionCommand& cmd,
    const GaitParams& g, double swing_remaining_time) const
{
    const auto& cfg = kin_.config(leg);
    const double T_stance = g.duty_factor / std::max(g.frequency, 1e-3);

    Vec3 hip_in_body = cfg.hip_offset_in_body;

    Vec3 target;
    target.x = hip_in_body.x + cmd.vx * (T_stance * 0.5 + swing_remaining_time);
    target.y = hip_in_body.y + cmd.vy * (T_stance * 0.5 + swing_remaining_time);
    target.z = -cmd.body_height;     // body 系 Z 上, 地面在 -body_height

    // yaw_rate: 落点旋转一个小角度, 对应每条腿的水平偏移
    const double yaw_offset = cmd.yaw_rate * (T_stance * 0.5 + swing_remaining_time);
    const double cy = std::cos(yaw_offset), sy = std::sin(yaw_offset);
    Vec3 rotated;
    rotated.x = (target.x - hip_in_body.x) * cy - (target.y - hip_in_body.y) * sy + hip_in_body.x;
    rotated.y = (target.x - hip_in_body.x) * sy + (target.y - hip_in_body.y) * cy + hip_in_body.y;
    rotated.z = target.z;

    // 步长上限 (相对于 hip)
    Vec3 hip_rel = rotated - hip_in_body;
    double r = std::hypot(hip_rel.x, hip_rel.y);
    if (r > g.max_step_length) {
        double s = g.max_step_length / r;
        hip_rel.x *= s; hip_rel.y *= s;
        rotated = hip_in_body + hip_rel;
    }

    Vec3 hip_target = kin_.body_to_hip(leg, rotated);
    hip_target = kin_.clamp_to_workspace(leg, hip_target);
    return kin_.hip_to_body(leg, hip_target);
}
```

`swing_remaining_time` 让 landing target 始终瞄准"未来触地时刻的 hip 位置"，而不是当前位置。

**plan() 主循环（修正版）：**

```cpp
std::array<FootTarget, lm::kLegCount> FootPlanner::plan(
    const RobotState& state, const LocomotionCommand& cmd,
    const GaitParams& gait, const ContactSchedule& sch, double dt)
{
    std::array<FootTarget, lm::kLegCount> out;
    const double T_stance = gait.duty_factor / std::max(gait.frequency, 1e-3);
    const double T_swing  = (1.0 - gait.duty_factor) / std::max(gait.frequency, 1e-3);

    for (size_t i = 0; i < lm::kLegCount; ++i) {
        auto leg = static_cast<lm::LegId>(i);
        auto& mem = memory_[i];
        const auto& ls = state.legs[i];
        const bool in_stance = sch.in_stance[i];

        if (in_stance && !mem.was_in_stance)
            mem.touchdown_pos = ls.foot_pos_body;
        if (!in_stance && mem.was_in_stance)
            mem.liftoff_pos  = ls.foot_pos_body;

        if (in_stance) {
            const double p = sch.stance_progress[i];
            Vec3 sp = mem.touchdown_pos;
            sp.x -= cmd.vx * p * T_stance;
            sp.y -= cmd.vy * p * T_stance;
            // 高度跟随 cmd.body_height 缓变 (避免 step 改变高度时支撑腿飞)
            sp.z = -cmd.body_height;
            out[i].position = sp;
            out[i].force_contact = true;
        } else {
            const double p = sch.swing_progress[i];
            const double remain = std::max(0.0, T_swing * (1.0 - p));
            mem.landing_target = compute_landing_target(leg, cmd, gait, remain);
            out[i].position = swing_trajectory(
                mem.liftoff_pos, mem.landing_target, p,
                std::max(gait.step_height, 0.040));   // 强约束: ≥ 虚位 ×2
            out[i].force_contact = false;
        }
        mem.was_in_stance = in_stance;
    }
    return out;
}
```

```cpp
    // foot-target 空间过渡: 在切换瞬间冻结 from-targets, 用 blend 逐渐过渡到 to-targets
    bool                           transitioning_{false};
```

**update() 主流程：**

```cpp
JointCommand LocomotionController::update(double t_now, double dt) {
    update_robot_state();                      // 反馈 → FK → state_
    auto cmd = cmd_filter_.step(dt, t_now);
    if (cmd_filter_.timed_out(t_now)) {
        cmd = {};
        cmd.body_height = sched_.gait_params().type == GaitType::STAND
                          ? state_.legs[0].foot_pos_body.z * -1
                          : default_height_;
        requested_gait_ = GaitType::STAND;
    }

    handle_gait_request(requested_gait_, dt);  // 处理切换 + 设置 transitioning_
    auto schedule = sched_.step(dt);
    auto targets  = planner_.plan(state_, cmd, sched_.gait_params(), schedule, dt);

    // 过渡: blend in foot-target 空间
    if (transitioning_) {
        const double a = smooth_step(transition_t_);
        for (size_t i = 0; i < lm::kLegCount; ++i) {
            auto& t  = targets[i].position;
            auto& tf = transition_from_targets_[i].position;
            t = tf + (t - tf) * a;
        }
        transition_t_ = std::min(1.0, transition_t_ + dt / transition_dur_);
        if (transition_t_ >= 1.0) transitioning_ = false;
    }

    JointCommand out{};
    for (size_t i = 0; i < lm::kLegCount; ++i) {
        auto leg = static_cast<lm::LegId>(i);
        Vec3 hip = kin_.body_to_hip(leg, targets[i].position);
        hip = kin_.clamp_to_workspace(leg, hip);

        lm::LegJoints<double> q;
        if (kin_.inverse_kinematics(leg, hip, q)) {
            out.positions.at(leg) = q;
        } else {
            // IK 失败: SafetyMonitor 决定是 hold 还是降级
            out.positions.at(leg) = state_.legs[i].joint_pos;
            safety_.report_ik_failure(leg, hip, t_now);
        }

        // WALK 锁 J1
        if (sched_.gait_params().joint1_lock_zero)
            out.positions.at(leg).j1 = 0.0;
    }

    // 关节限幅
    safety_.enforce_joint_limits(out, kin_);
    return out;
}
```

## 十四、实施顺序

### Phase 0: 测量 + 单腿台架（关键, 1 天）

a. 用卷尺/卡尺确认 `hip_offset_in_body`、站立 foot 在 hip 系坐标，写进 `robot_geometry.yaml`。
b. 单腿（默认只有 LB 在 `real_motor_controller` 里 enable）跑 `pose_hold_tool` 把腿摆到 (j1=0, j2=0, j3=0) 与 IK 解出来的角对照，确认 `kJointSigns` 与 `knee_offset_rad` 自洽。
c. 写 `LegKinematics::self_check()`，FK(0,0,0) 必须命中 `nominal_stand_foot_hip ± 5mm`。失败就先停。

### Phase 1: 站立 + IK 验证（2 天）

1. `LegKinematics`（FK / IK / clamp / self_check）+ 单测 `FK(IK(p)) ≈ p` 跨整个工作空间。
2. `LocomotionController` 最简：只有 STAND，`SafetyMonitor` 接住 IK 失败。
3. 接 ROS 节点。地面跑通：高度上下、left/right 站姿。

### Phase 2: STEPPING 开环（1 天）

4. `GaitScheduler` + `FootPlanner` 的 swing 部分（landing target 直接用 hip 正下方）。
5. STEPPING（vx=vy=0）跑通，调 `step_height` 与频率。

### Phase 3: TROT 开环（2 天）

6. `FootPlanner` 接通 Raibert 落脚 + 支撑相线性后推。
7. 用 `cmd_filter` 限速接通 `xbox_input_node`，先低速 `vx_max=0.2`。

### Phase 4: 闭环 + 稳定性（2 天）

8. `set_motor_feedback` 接通 → FK 写入 `RobotState`。
9. swing 起点改用 `state_.legs[i].foot_pos_body`（不再用名义起点）。
10. `clamp_to_workspace` 全开。
11. landing target 每周期更新（已在 v2 里）。

### Phase 5: WALK + 步态切换（1 天）

12. WALK 步态（J1 锁零）跑通，沿用现有 `walk_phase_offset_for_leg` 偏移序列。
13. STAND ↔ 任意 + 任意 ↔ STAND 的 foot-target 空间 blend；TROT↔WALK 必经 STAND。

### Phase 6（可选）: IMU + BodyController（2 天）

14. `BodyController`：IMU 来 roll/pitch → 修正 `body_height` 在每条腿 hip 系下的投影；CoM 简单投影到 stance 多边形内。

## 十七、验收准则

每个 Phase 结束做以下断言：

- **Phase 0**：`self_check()` 通过；电机断电下手动到站立位，电机角与 `kJointSigns` 一致 0±0.02 rad。
- **Phase 1**：站立 5 分钟无漂移；高度命令 0.27→0.32 跟随，无超过 ±5 mm 误差。
- **Phase 2**：STEPPING 30 s 不绊脚，足端实际抬腿 ≥ 30 mm（IMU 加速度判断或视觉）。
- **Phase 3**：TROT 0.2 m/s 直行 5 m 不摔，姿态 |roll|<10°、|pitch|<10°。
- **Phase 4**：vx 阶跃从 0 到 0.3 m/s，落脚点变化在 200 ms 内响应；强行把腿拉离名义位置，下一摆动起点用实际位置。
- **Phase 5**：STAND→TROT→STAND 三次切换，无关节抖动 > 0.3 rad/40ms。

## 十八、未解的开放问题（需要现场决策）

1. **触地检测**：当前只有电机扭矩，没有足底力。要不要在膝关节扭矩做阈值判断当 `in_contact` 用？还是先信调度（in_stance==true 即视为触地）？
2. **轨迹时间补偿**：`real_motor_controller` 5 ms 周期 + CAN 延迟约 1–2 ms。要不要在 `JointCommand` 带 `timestamp` 让电机层做最近邻外推？
3. **IMU 没接通时**：BodyController 完全跳过即可，但是否需要在 `LocomotionDebug` 标注 `imu_active=false` 给调试用？
4. **`step_height` 自适应**：是否随 `vx` 增加而增加（高速更高的弧度）？暂留固定值。
